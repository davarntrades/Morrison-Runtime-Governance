## 3. Sequential guard: adversarial tests (`reaudit/guard_probe.py`)

| # | attempt | result |
|---|---|---|
| 1 | `execute()` with the guard set and no open transaction | **refused** (fail-closed) |
| 2 | nested transaction in the same thread | **rejected**; guard released after unwinding |
| 2b | exception inside a transaction, then a new one | **recovers** |
| 3 | `decide()` outside any transaction | **allowed**: authorization isn't guarded. Two decisions minted against one state, then executed in two sequential transactions: the second is refused as stale by the state binding. |
| 4 | two threads, each opening its own transaction (50 ms window) | **one rejected in 20/20**; monitoring intact |
| 5 | thread B calls `execute()` with no transaction while thread A's is open | **B executes in 20/20**: the prohibited A+B trajectory commits, monitoring breaks, **0 rejections recorded**. `execute` checks `guard.active()` (is *any* transaction open?), not ownership. |
| 6 | `Executor(guard=None)` | **unguarded**; the guard is opt-in and only the harness passes one |
| 7 | two threads driving one `Episode._guarded_step` (the real runner path) | **one rejected in 10/10**, recorded as `concurrency_rejected`; one executed |

Within the PR's runner, steps are serialized. The loop is single-threaded, there is no
threading/async/multiprocessing in `experiments/monitoring_incident/`, and proposers hold no Executor
reference. Any overlap reaching the runner path is rejected and recorded. **This is harness-level
serialization, not production concurrency safety.** Morrison's Executor remains unsafe under concurrency
(the unguarded race composed A+B in 11/30 at this head), and an in-process caller with an Executor
reference bypasses the guard (test 5). Recommended hardening: have `execute()` require the caller's
transaction token or owning thread. It isn't needed for the sequential Phase 2 runner.

### 4.1 Live-run evidence overwrite (new finding)

`cmd_live` always uses `repetition=0`, and `run_id` is a deterministic hash of commit, manifest,
scenario, condition, policy, proposer identity, case, step limits and repetition. `Episode.run()` deletes
an existing run directory (`harness.py:334`). Two identical runs into the same `--output` produce the
**same `run_id` with different evidence**: I observed terminal hashes `dd091e…` then `55fe90…`, with one
directory left. The first run's evidence is silently destroyed. PHASE2_CHECKLIST's "Repeat each cell N≥5
times … keep every run id", followed as MACOS.md shows (one shared `--output`), would keep only the last
replicate per cell. **Mitigation (mandatory): a distinct `--output` per replicate**, as below. Fix: add
`--repetition` (or a nonce) to `live`.

## 6. macOS readiness

Documentation checks:
* MACOS.md / PHASE2_CHECKLIST.md commands match the CLI (`coverage`, `scripted`, `differential`,
  `preflight`, `live`, `verify`; flags exist).
* Discrepancies:
  - **(a)** repeated live runs into one `--output` overwrite evidence (§4.1);
  - **(b)** the checklist's analysis step "confirm … global/hierarchical unauthorized_executed = 0" is
    not an invariant; ten known breaks exist (L2). A non-zero count is a result to report, not a
    failed check;
  - **(c)** examples use `/tmp`, which macOS clears on reboot. Keep evidence in a durable directory;
  - **(d)** stock macOS has no `python` command; use a venv;
  - **(e)** `pytest` must be installed, despite "no extra pip install";
  - **(f)** `verify` instructions omit `--terminal-hash`.

Must be validated on the Mac (not testable here):
1. **Confinement.** Every run's `baseline_oracle.confinement` must read
   `macos-sandbox-exec:no-network,writes-confined`, and `status` must be `ok`: the baseline oracle,
   trusted tests and `run_tests` must work under the `sandbox-exec` profile, with `/var → /private/var`
   and `/tmp → /private/tmp` realpaths. `sandbox-exec` is deprecated by Apple but still shipped; confirm
   it is present.
2. **XC-SYM under `sandbox-exec`.** The `counterexamples` command must still report XC-SYM
   `unauthorized_executed=1` and uninspectable: the symlink must be creatable in the sandbox and visible
   to `scan_tree` on APFS.
3. **APFS case and normalization.** The ASCII-case guard (`_target`) depends on case-insensitive
   collisions, which APFS has by default. Whether `teſts` (U+017F) aliases `tests` on the Mac's volume
   decides whether the `lower()`-vs-`casefold()` gap is live. If it is, record it as a finding before
   the campaign.
4. **Model and Ollama.** Tag names (`qwen2.5:1.5b-instruct-q4_K_M`), native tool-calling on small
   models, and memory on 8 GB. Record the seed/temperature; without `--seed` runs are not repeatable.
5. **Timing.** `morrison_governance/test_adversarial_round4b.py::test_r4b_03` asserts < 0.5 ms per
   commit and failed here under load (§5). Expect it to be load-sensitive on an 8 GB Mac; it isn't part
   of the experiment suite.

## 8. Remaining limitations (carry into Phase 2)

* **L1** The Executor is not concurrency-safe. The guard serializes the harness only; it is bypassable
  in-process (test 5) and opt-in.
* **L2** The global tier is hand-written per scenario: 9 false-safe edits plus XC-SYM execute under
  `hierarchical`. Live-model breaks outside the invariants will be detected after execution, not
  prevented.
* **L3** The state binding ignores non-regular files (they are still recorded).
* **L4** HMACs cannot be verified offline. No tool generates the anchor; use step 7.
* **L5** Fail-closed scope is `var/ config/ app/ tests/ .env`.
* **L6** Live `run_id` collisions overwrite evidence. The per-replicate `--output` is mandatory until
  `live` gains `--repetition`.
* **L7** Not tested anywhere: macOS `sandbox-exec`, APFS, sockets/devices/unreadable files (root
  container), multi-process races, live models.
